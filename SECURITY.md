# Security reporting and supported scope

Do not publish vulnerabilities, credentials, private keys, plaintext, or
exploit steps in a public issue. If GitHub's **Report a vulnerability** option
is available for this repository, use that private channel. If it is not
available, ask a maintainer in a public issue to establish a private channel
without including sensitive details. The maintainer still needs to confirm a
stable private reporting route before a JOSS submission.

The current development tree is a proof of concept; no production support or
response-time commitment has been established. The supported behavior and
known limitations are in `docs/reviewer-guide.md`, `docs/threat-model.md`,
and the production backlog. Report the affected revision and a minimal
synthetic reproduction when safe to share.
