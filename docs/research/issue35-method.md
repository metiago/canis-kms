# Issue #35 evidence-synthesis method

## Purpose and boundary

This is a retrospective synthesis of already observed CANIS research evidence. The question in the [Issue #31 protocol](issue31-protocol.md) is how correctness, resource use, and availability change when Java services exchange encrypted files asynchronously through CANIS under shared trust. The available records answer bounded parts of that question. In particular, they do not contain the protocol's scheduled outage series or its original three-path local AES-GCM/local-envelope/CANIS comparison. This synthesis neither changes that protocol retrospectively nor treats missing work as completed.

No new experiment, measurement, pooled estimate, confidence interval, or cross-study effect size is produced for Issue #35. The only Issue #35 verification is read-only checking of existing published artifact sets. The report is [issue35-results.md](issue35-results.md).

## Included evidence and selection rules

Include the final or explicitly identified acceptance series from [JOSS-01](joss01-method.md), [CODE-02](code02-method.md), [CODE-03](code03-method.md), [Issue #31 CANIS baseline](issue31-baseline-method.md), [Issue #32](issue32-method.md), [Issue #33](issue33-method.md), and [Issue #34](issue34-method.md). Use each corresponding `*-results.md` record as the interpretation source, and its linked CSV, JSON, manifest, method, runner, analysis, and verifier as provenance. The [research index](README.md), [backlog (archived)](repository-cleanup-report.md#archived-files), [manuscript](../../joss-papers/paper.md), and [engineering guidelines](../../AGENTS.md) provide context and claim boundaries, not additional measured outcomes.

Prefer the final series where a record distinguishes final from preliminary attempts. Retain failed and preliminary attempts as methodological limits; do not add them to final success counts. Do not combine file counts across studies into a reliability rate: the workloads, revisions, fixtures, outcome definitions, and observation periods differ. Keep the Issue #31 absolute CANIS baseline separate from Issue #32's paired transport-path comparison. The latter's A/B arms are TLS/mTLS CANIS and a research-only loopback plain CANISP fixture, respectively; they are not the local AES-GCM and local-envelope controls named A/B in the original Issue #31 protocol. Treat the plain fixture only as an isolated research comparator. The supported product path remains TLS 1.3.

For each included study, extract the question, prespecified or amended method, source state, host, workload, observed outcomes, artifact links, and stated limitations. A result on a dirty working tree remains a working-tree result even if a later commit contains similar files. A fixed-revision result applies only to that study and revision. A passing artifact verifier checks consistency of retained records; it does not reproduce the execution or validate removed private fixtures. Historical use of a predecessor and author-attested continuity are contextual evidence, not current-code deployment or external adoption evidence.

## Claim and consistency procedure

Every substantive conclusion in [issue35-results.md](issue35-results.md) points to the relevant study record or raw evidence. Report categorical counts and descriptive values exactly as recorded. Distinguish observation from interpretation, and use the method's units and denominator. In particular, process peak working set is not JVM peak heap, an exit-heap value is not a peak, a connection-plus-login interval is not TLS handshake time, and a key-request interval is not pure network time. A scheduled 60-second consumer delay is part of end-to-end latency, not cryptographic processing time. Positive byte comparisons establish correctness for tested fixtures, not a general reliability or availability guarantee.

Review the records for apparent conflicts by checking their source revision, fixture, TLS identity, fault state, and outcome definition. The JOSS-01 test shares one client certificate among distinct credential identities; Issue #33 uses distinct certificates. Issue #33's successful restart uses an intact database and matching master key; Issue #34's rejected restarts use deliberately corrupted or mismatched material. Issue #34's independent audit-file hash changes do not imply a built-in audit verifier. Record any unresolved mismatch as a limitation, not an averaged result. The original synthesis only audited [the manuscript](../../joss-papers/paper.md); the later claim-traceability follow-up aligns its wording and records every manuscript assertion in [issue35-claim-matrix.md (archived)](repository-cleanup-report.md#archived-files).

## Reproduction and artifact-check procedure

The individual methods specify fixture generation, platform prerequisites, expected output, cleanup, and exact execution commands. Those commands appear in the report for an independent reader; they were not run for this synthesis. Research runners generate fresh temporary credentials, keys, databases, and synthetic payloads. Successful fixtures are removed only after path and marker checks; failed private fixture roots require inspection and must never be published. Public artifacts are sanitized JSON, CSV, source hashes, and SHA-256 manifests. Reproductions generate different random cryptographic material, PIDs, timestamps, and ciphertext; compare predefined outcomes and invariants rather than byte-identical run artifacts.

For this synthesis, run only the read-only Issue #32, #33, and #34 artifact verifiers against retained repository data. Do not pass manifest-writing options. Record the verifier output and limits in the report. The CODE-03 and Issue #31 CSV hashes, JOSS-01 Surefire outcome, and CODE-02 CI result are taken from their dated result records; they are not newly reproduced here. The source records specify the commands for regenerating descriptive tables or checking individual hashes when a reviewer needs to do so.

## Acceptance rule

Issue #35 can consolidate the completed, bounded studies, give a traceability matrix, and document missing evidence. Its backlog acceptance requires that **each paper claim** trace to a fixed-revision result and reproduction steps. The [manuscript claim matrix (archived)](repository-cleanup-report.md#archived-files) supplies a fixed repository evidence-artifact revision and reproduction route for each current claim, while explicitly identifying dirty-tree executions. The existing record still does not satisfy the fixed-execution gate for those studies or the unexecuted parts of the original research question. Mark those items open. Do not declare the broader study, a release, or the JOSS manuscript publication-ready merely because this synthesis exists.
